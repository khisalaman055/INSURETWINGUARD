# INC-D1-001: Controlled CPU Saturation

## Summary
A controlled Python busy-loop was started in the local Ubuntu/WSL2 lab
to simulate a CPU-heavy workload.

## Detection
Command: ps aux --sort=-%cpu | head -n 5

## Evidence
- Test process PID: 10772
- Process: python3 -c 'while True: pass'
- Observed CPU usage: 99.9%
- Observed memory usage: 0.1%
- Process state: R (running/runnable)

## Mitigation
Sent SIGTERM using kill -TERM 10772.

## Recovery Verification
- Shell reported the background job as Terminated.
- A subsequent process listing showed no comparable CPU-heavy test process.
- Top listed processes showed 0.0% CPU in the captured snapshot.

## Root Cause
The intentionally started Python busy-loop continuously consumed CPU.

## Prevention / Learning
- Capture a baseline before reproducing an incident.
- Verify process identity before terminating it.
- Prefer graceful termination before force-killing.
- Verify process exit and application health after mitigation.

## Scope
Local training simulation only; not a production outage.
